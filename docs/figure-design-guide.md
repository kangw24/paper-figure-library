# 通用论文绘图指南

动笔前，先补完一句话：“看完这张图，读者应该能＿＿。”用“指出”“比较”或“解释”这样的动词填写。比如，“读者能找到装置里发生变形的位置，并看出增加载荷后它怎样变化。”这句话已经给出了两幅子图的内容，也说明了它们为什么要放在一起。

## 确定每幅图要回答的问题

| 图的用途 | 读者想知道什么 | 可以怎样画 |
| --- | --- | --- |
| 论文首图（teaser） | 这篇工作解决了什么问题？核心想法或效果是什么？ | 选一个能看清差异的例子，让读者看到原来的困难，以及新方法带来的变化。 |
| 方法与架构图 | 一个输入怎样变成结果？关键步骤发生在哪里？ | 用同一个例子贯穿主要步骤，在关键处画出中间状态；复杂模块可以局部展开。 |
| 实验与结果图 | 条件改变后发生了什么？哪些观察支持这个判断？ | 把最需要比较的结果放在一起。在测量位置或实验条件影响解读时，配一幅对应的示意图。 |

## 让子图之间的关系看得见

安排相邻两幅子图时，问一句：**读者从上一幅带着什么去看下一幅？**

| 想让读者做的事 | 两幅图之间怎样对应 |
| --- | --- |
| 比较两种方法或条件 | 同一个样本用同一视角、裁剪范围或时间窗口呈现。需要直接比较数值时，统一单位、坐标范围和长宽比。 |
| 从全貌看局部 | 在全貌中指出一个部件或位置，再把它展开。局部可以换视角或改画剖面，保留能认出来的轮廓、标记或名称。 |
| 理解一个过程 | 让同一对象出现在前后两个状态。保留位置或标识，在发生变化的部位突出差异。 |
| 把场景和测量对应起来 | 在示意图上标出采样位置或观测量，在数据图中沿用该标记和单位。读者就能从“在哪儿测”读到“测到了什么”。 |

先用邻近、对齐和共同标记建立联系。遇到多个相似部件、读者很难确认对应位置时，再用一根短引线指到目标。可对照库里的[整体与局部范例](../multipanel/README.md#scales)、[引线与局部展开范例](../multipanel/README.md#cross-panel-links)和[共用数据与坐标范例](../multipanel/README.md#linked-data)。

## 分配版面与文字

- **面积跟着阅读任务走。** 先给核心现象或最细的结构留足空间。需要逐项比较的面板对齐、等大；辅助场景画到足以辨认即可。把图缩到正文宽度，再判断各部分的比例。
- **重复出现的视觉元素沿用同一含义。** 同一对象跨图保持颜色和名称，曲线和点的含义用一致的线型或标记表达。按最终刊印尺寸确定字体层级和线宽。辅助线只画在需要对齐时刻、定位阈值或读数的位置。
- **文字放在读者用得到的地方。** 变量、单位和部件名就近标注。样本来源、实验设置、特殊条件和结果解释写进题注。检查图例时，可以试着把曲线名直接放在线尾，看看哪种读起来更顺。

## 从草图到交付

1. **定目标。** 写下读者看完应当能回答的问题，列出回答它所需的场景、数据或对照。若一张图承担两个独立结论，先考虑分成两张。
2. **带着构图问题找参考。** 例如要画“全貌和局部”，就观察参考图在哪里标出位置、局部放大多少、用什么保留对应关系。把参考图简化成几块灰框，换上自己的材料，判断这套安排是否仍然成立。
3. **先排黑白草图。** 用真实的对象名、代表性样本和大致正确的数据形状占位。暂时遮住题注，试读一遍。如果在两幅子图之间需要来回寻找对象，先调整位置、对齐或标记。
4. **做完一张，再扩展整套。** 选一张有代表性的图定下字体、配色、线宽和标注方式。数据图用脚本从原始数据生成，示意图保留可编辑的矢量源文件；同一套图复用样式，各张图按内容排版。
5. **从交付文件验收。** 把导出的 PDF 放到正文实际宽度，确认第一眼能看到主角，最小文字和曲线仍可辨。逐对核对用于比较的样本、条件、单位和尺度。交付矢量文件时，重新打开检查字体、特殊符号、裁切和文字可编辑性。
