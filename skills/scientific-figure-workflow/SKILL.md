# 科研制图工作流

把研究关系转化为可检验、可阅读、可编辑的图。先判断每个对象与连接表达什么，再决定版式和视觉处理。本 skill 总结了一次 AI4PDE 中期汇报的长期制图迭代，包含成功改法，也保留失败原因与适用边界。

## 先辨认任务和规则来源

- 当前用户指令优先。延续已经批准的内容、颜色、版本和工具路径；不要每轮重新设计所有部分。
- **通用底线**：科学关系正确、数据身份明确、来源可追溯、实际渲染检查、诚实报告编辑范围。
- **本用户长期偏好**：紧凑、层级明确；图内英文、题注图外；不默认添加卡片、灰色小字、装饰性口号和页脚总结。详见 [排版与风格](references/03-layout-and-style.md)。
- **当前项目取向**：多子图、内容充实的综述式 teaser。不能据此把所有项目改成综述图，或改写整个素材库的永久选图标准。
- **案例参数**：六图编号、特定 PDE、画幅、配点数、5 分钟汇报时长仅属于案例，不能自动复制到新项目。
- 用户说“AI 味”时，将反馈定位到具体视觉对象；这是风格评价，不是识别内容是否由 AI 生成的证据。

## 执行顺序

### 1. 建立当前状态

查看最新实际文件、完整预览、研究纲要和最近批准的方案。旧方案只是历史证据；以最新指令和核实后的科学内容为准。

建立图清单，记录编号、用途、主张、当前版本、待解决问题、锁定对象、最终载体。多图任务不能因聚焦局部而漏掉其他图。本案例为 01、02、03、04、05、08，不是 01–08 连续八图。

遇到“保存一份再改”，先备份。大幅改版也保留可恢复版本。不要覆盖作者原始素材，不把每次小修都复制成不知哪份最新的十个目录。

### 2. 先作参考证据，再作布局

从现有仓库中打开与表达关系相近的真实预览，选择主参考及必要的局部参考。记录借鉴的分组、图文邻接、颜色角色、局部放大和箭头用法；仅列论文名不算对标。

不要把“Figure 1”“顶会”“Oral”当作适配性证明。teaser 是作用，architecture 是内容，编号不是分类。缺少源文件时如实说明，不能用自绘元素冒充抓取结果。

### 3. 为每图写内容契约

用 [图形简报模板](assets/figure-brief.template.json) 记录：

1. 读者应理解的核心关系，以及每个子图增加的独立信息。
2. 每个对象的来源和身份：符号、解析示意、数值参考、合成观测、固定试探场、实际训练预测。
3. 输入、输出、参数、目标、约束，以及箭头起点、终点和含义。
4. 公式成立的假设、需要计算的量、尚无证据的结果。
5. 本次允许变化和锁定的内容。

模板是可复用结构，不要求每次产生全套文档。不能为了补满画面而编造实验、权重、误差或性能曲线。

### 4. 先处理科学机制，再分配画幅

检查模型输入是否误接监督目标、软惩罚是否被画成硬保证、示意数值是否被当成实验结果、不同假设下的公式是否被强行并列。

科学复审不自动授权收窄范围。优先修正关系、增加必要条件、区分概念和补充局部机制；需要调整研究主张时明确解释，不能静默删主题来规避难题。

### 5. 按语义布置二维结构

在最终画幅中先摆最长公式、主科学对象、图例和标签。按内容分配面积，不先画等分容器再往里填。

- 将同一机制的图、公式、标注排紧，形成局部可读单元。
- 用并列比较、嵌套展开、分支汇合、定位放大表达二维关系。
- 缩短空箭头通道，避免独立的公式墙和整列空白。
- 增加的是不同关系和真实细节，不是重复图、口号、子图数量或无关小数字。
- 各图可用不同布局；字体、颜色含义和线条语义保持一致。

规划必须含可看的空间预演；用户要求“按方案改”时，交付实际修改后的完整草图，不能再次只写计划。

### 6. 落实视觉与公式

优先用现有矢量、绘图工具、实际计算和 TeX 构建科学对象。不要用生成式位图制作承担精确机制、公式或结果证据的图；明确需要概念插画时可另行考虑，并标明角色。

配色拆成分类色、连续场色图、线条/背景三个独立系统。只改用户指出的系统，不把“减少多彩卡片”解释为所有科学图去色。公式保留 TeX 源，检查基线和实际视觉字号。

### 7. 实际复审与修订

查看完整图和关键局部，并在最终使用尺寸检查。顺序：科学错误 → 视觉误导 → 阅读与裁切 → 风格。

用户明确要求多智能体或有适用指令时，可分别委派科学机制、构图密度、字体/配色审查；否则不要自动启动代理。每条意见必须指明对象、问题、依据与改法。主 agent 汇总并落实，不能把子 agent 的认可当成用户认可。

使用 [修订记录模板](assets/revision-log.template.json) 追踪实际改动与锁定对象。对“删干净”，检查全图所有实例、生成函数和导出版本，不只修改一个样式定义。

### 8. 完成交付

提供完整预览和实际文件；说明文本是否可编辑、公式是否轮廓化、场图是否位图、AI 是否经 Illustrator 原生保存。结构检查不能代替视觉或科学验收。

涉及 GitHub 时按既有分类落盘并串联 Markdown；有上传授权后提交，避免强推。没有要求安装 skill 时，不擅自改用户全局技能目录。

## 小修订快捷流程

读取最新稿 → 定位具体对象 → 锁定其余科学数据和样式 → 保存必要备份 → 修改全部相关实例 → 渲染全图与局部 → 给出文件和简短变化说明。

不要让完整流程成为反复确认、额外审批或长篇说明的借口。当前授权内能完成的工作直接完成。

## 工具与能力边界

- `scripts/audit_svg.py`：只读 SVG 结构预检。用法及限制见 [交付文档](references/05-illustrator-and-delivery.md#svg-结构预检)。不判断美丑、科学正确性或 Illustrator 导入结果。
- 使用当前可用的搜索、仓库及 UI 工具；不写死某次工具名、tab ID 或本机路径。
- PPT、PDF、中文 LaTeX 等任务同时遵循环境中相应技能与用户配置；它们处理工具约束，本 skill 处理科研内容与图形组织。
